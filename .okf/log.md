Screenshot feature: opt-in real-pixel screenshot of the picked element, promoted by the payload benchmark. `src/types.ts` gained `ScreenshotRequest { rect, screenX, screenY, chromeLeft, chromeTop, dpr }`, `PromptRequest.screenshot?`, `PromptResponse.screenshot: string | null`, and `StateResponse`'s live branch gained `screenshot: 'available' | 'unsupported' | 'off'`. Client: a `📷 attach screenshot` checkbox between the textarea and the spawn buttons, visible only when live state reports `screenshot: 'available'`, checked state persisted in `localStorage['herdr:shot']`; checking it at send time hides the popup, keeps/draws the hover outline+chip on the picked element, waits two animation frames, then reads `window.screenX/screenY`, `chromeLeft/chromeTop` (from outer/inner window dimensions), `devicePixelRatio`, and the picked element's live bounding rect into the request body. `window.__herdr.screenshotEnabled()` added for tests. New test fixture `src/__tests__/helpers/fake-screencapture.sh` (executable, writes a fixed 1x1 PNG to its last argument, `FAKE_SCREENCAPTURE_FAIL=1` makes it fail without writing) backs `src/__tests__/screenshot.spec.ts` and `e2e/screenshot.spec.ts`; `e2e/helpers/servers.ts`'s `StartDemoOptions` gained `plugin?: Partial<Options>` merged into `herdr()` (socketPath always wins from the fake). Never runs the real `screencapture` in tests.

In-flight outline race fix: `mountRoutes`'s `/prompt` handler calls `watchAgent` (subscribing to herdr) before sending the HTTP 200, so a fast `working`/`blocked` event could reach the browser before the client had recorded which pane was in-flight, and get silently dropped - the direct cause of `e2e/status.spec.ts`'s "shows a waiting toast when the pane blocks" failing about half the time. Fixed client-side in `src/client/index.ts`'s `send()`: the in-flight pane/element is now recorded (and the box/chip shown, chip reading `→ <title> · sending…`) synchronously before the `/prompt` fetch is issued, not after its response arrives; a non-200 response or network error clears it again. `startInflight` gained a `chipSuffix` parameter (default `'working…'`) and a `hidden` parameter (kept for the screenshot capture window below); `renderInflightChip` gained the same suffix parameter. A second-order race surfaced by the fix itself: a herdr:status push can now arrive and settle (blocked/idle) the pane before the `/prompt` response itself resolves, so the response handler's own "Sent to …" toast could clobber the settle toast already shown - fixed with an `inflightSettled` flag, set by `settleInflightFinished`/`settleInflightBlocked` and checked before showing "Sent to …" or retargeting. Screenshot capture (above) reuses the same pre-fetch tracking but keeps the box/chip hidden (`startInflight(..., hidden: true)`) until the response settles, so the client's own overlay never lands inside the captured crop. `e2e/status.spec.ts` gained a `waitForInflight` helper (polls `window.__herdr.inflight()`) used before pushing test events in both tests, replacing a single-shot, non-retried check; `sendPrompt` now waits for a preselected agent option before sending, closing a separate, unrelated race where `Enter` could land before `GET /state` resolved and fall back to clipboard mode instead of posting `/prompt` at all (only surfaced under `--repeat-each` stress). Verified with `npx playwright test e2e/status.spec.ts --repeat-each=8 --workers=1`, 100% green across repeated runs.

Multi-select: shift+click while picking adds an element to the selection (up to 5 total) instead of finalizing the pick; a plain click always finalizes. `PromptRequest` gained `extras?: ElementInfo[]` (up to 4, validated in `src/http.ts` the same way as `element`, any invalid item rejects the whole request). `composePrompt`/`renderAttachment` in `src/compose.ts` render each extra as a numbered `Element N:` block (inline) or `## Element N` section (attachment), rewriting the extra's picked-marker to `data-herdr-picked="N"`; `postPrompt` absolutizes every extra's hint. Client gained persistent numbered outline boxes for the selection, a `MAX_SELECTION` cap of 5, and `window.__herdr.selection()` for tests.

Benchmark run and decision recorded: the pre-registered payload benchmark (protocol in `docs/payload.md`) ran on 2026-09-07 against Claude Sonnet 5, 10 tasks × 3 variants × 1 repetition, 30 headless runs, ≈$4 total cost. Results: `text` and `text+shot` (bare screenshot) both score 60% on visual tasks; `text+shot+outline` scores 80% (+20 points) at a 23% turn cut (6.0 → 4.6 mean turns), with no regression on edit-task success (100% across all variants). Per the pre-registered decision rule this promotes the outlined screenshot into the product as an opt-in feature and rejects the bare/no-outline variant outright - implemented as the screenshot feature above. Raw data and rendered summary in `docs/bench/2026-09-07/`. `.okf/payload.md` and `.okf/benchmark.md` updated to `status: stable` with the results table and decision.
